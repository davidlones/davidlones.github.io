Tower Notes

Operational caveats and repair context.
  • The current app drives the recovered tower through the SolBridge server command path instead of raw /setblock, because direct metadata writes do not propagate redstone correctly in this lab.
  • The face painter uses a corrected SolBridge display-driver command because the recovered redstone bus is active-low and cross-coupled in its current state.
  • The hardware panel still exposes the original levers and button for calibration, repair, and manual experiments.
  • SolBridge Rotation Assist is the current band-aid: turning it off leaves rotation pulses physical-only so players can debug the vanilla handoff without the mod advancing the face.
  • Sol can use the same corrected display path through /sol clock <value>, chat prompts, or written pages tossed at the entity. Remembered redstone controls are reactivated by stored coordinates, not player proximity.
  • The front-face mechanism sits deeper in the tower than the service levers. If the external face drifts after raw hardware changes, apply the face mask again to restore the visible display.
