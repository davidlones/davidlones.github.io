What this is

Recovered world, rebuilt route, custom portal hardware.

The Neoriris clock tower is an old redstone monument from a recovered Minecraft world. The current pack preserves the tower, runs it on Forge 1.12.2, and layers in PortalGun, Cloudflared multiplayer, the custom Neoriris Portal Door mod, and the custom SolBridge orb familiar.

The custom mod adds survival-craftable glowing portal buttons: Button A, Button B, and an Entangled Wall Button Pair kit. Each button can mount to a wall, floor, or ceiling and turns the largest complete rectangular surface beside it into one architectural portal. Entangled kits unpack into paired A/B buttons sharing a hidden server-generated UUID, so two players can name their routes the same thing without cross-linking portals.

Neoriris Portal Door 0.1.10

Custom Client + server mod id: neoririsportaldoor

Craftable Button A and Button B hardware appears as compact glowing portal buttons placeable on walls, floors, and ceilings. Each button detects the largest complete rectangular surface of matching blocks beside it, up to 16x16, then creates one continuous PortalGun/World Portals endpoint rather than a grid of small portals. The paired surfaces must have matching width and height because PortalGun 7.1 cannot safely persist unequal linked bounds. Empty-hand pressing latches the pair open until either detected surface is broken; redstone applied without pressing retains momentary control and a one-second close grace. Active buttons hide, lose collision, and become part of the rectangular live view, then reappear when the portal closes or fails. Neoriris-owned portals use a rectangular stencil with no oval ring, while ordinary handheld Portal Gun portals remain unchanged. Entangled Button Pair kits still unpack into matching A/B items with a hidden server-generated PairId, so route labels are lore, not identity.

Lore role: the clock tower's red/blue iris language. Lapis and redstone become addressable doors, turning old circuitry into a dimensional route board.

SolBridge 0.4.3 - Syzygy Console and SolScript GPIO

Custom Client + server mod id: solbridge

Adds Sol, a floating dark orb familiar with the three-way FOLLOW -> STAY -> FREE ROAM state cycle, persistent Gemma-planned contextual autonomy, reversible temporary builds, /sol commands, archive and inventory layers, safe JSON action execution, redstone/tower controls, music-reactive rendering, custom records, owner-only Sol Vision, and the Syzygy Console.

SolBridge 0.4.3 focuses the Syzygy Console as an in-world programming terminal: the GUI keeps live command output and scrollback in the item UI, adds Help, Self-test, and Pulse Note controls, and exposes circuit-aware help note|gpio|script|disc|commands topics. Note-block output follows a straight redstone wire run such as the current west-side console-to-note circuit.

The generated-concept skin now has an unmistakable disc mouth and three independent live lamps: amber for a loaded disc, cyan for playback, and red for the current beat, GPIO, or note pulse.

Lore role: Sol is the local shell of the noticing intelligence, and the Syzygy Console is its physical terminal: a jukebox whose CPU clock is music, whose screen is the sky, and whose data bus is redstone.

Syzygy Console / GPIO programming

In-game terminal, live UI console, and six-sided redstone bus.

The Syzygy Console is SolBridge's physical terminal block: disc slot, jukebox clock source, SolScript interpreter, note-block controller, SolNet node, and six-sided redstone GPIO. Right-click with a disc inserts and starts playback; right-click empty-handed opens the terminal GUI; sneak-right-click ejects the disc.

SolBridge 0.4.3 keeps terminal output inside the GUI while it is open, so help, status, note, jukebox, SolScript, and self-test results remain in the live console rather than cluttering chat. The GUI adds direct Help, Self-test, and Pulse Note controls; history scrolls with the mouse wheel or PageUp/PageDown.

Manual note output

gpio set west 0

Bare note or note read only inspects the circuit. gpio set west 0 holds the wire low when a playing disc would otherwise keep treble power on the west face; note play west creates a clean rising pulse; gpio clear west restores automatic music-driven output.

net set <side|all> <power> [radius]

net clear <side|all> [radius]
on note then <command>
on audio then <command>
if beat > 10 then pulse south 15 2

All six sides default to automatic output: north amplitude, south beat pulse, east bass, west treble, top visible celestial authority, and bottom terminal/program status. Read mode makes a side an input, write mode lets scripts drive it, manual mode holds a stable power, and pulse mode temporarily overrides the side for a bounded number of ticks.

Tower controls

Readable control surface for the recovered display.

The tower has two control layers. The original floor hardware still exists: a manual-enable lever, a clock-power lever, a manual-rotation button, and seven bit levers labeled by the signs as Up = 1 and Down = 0. The recovered redstone bus is active-low/cross-coupled, so the web app also exposes a corrected face driver that writes the visible seven-segment wool/piston cells directly.

The result is practical: use the painter when you want the front display to match a chosen symbol, use the raw hardware panel when calibrating the original circuit, and use Sol commands when you want the orb or a tossed written page to perform the same action in-world.

Open Control Surface Open Raw Switch Panel

Face painter

Applies a seven-segment mask through /sol tower face <bits>. This is the reliable path for numbers, A-F, dash, underscore, or hand-painted faces.

Hardware panel

Uses /sol tower manual, power, bits, and rotate to operate the original lever/button path without hiding the broken-state behavior.

Sol automation

Chat or book prompts can request /sol clock 5, nearest redstone activation, or remembered redstone activation. Clock-face requests are global; remembered controls use stored coordinates.
