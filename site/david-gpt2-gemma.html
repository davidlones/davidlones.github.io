    Everything after David-GPT-2> is predicted continuation text. A length_limit stop means the configured token budget ended before a structural end-turn token, so the final sentence may be incomplete.

LLM-first operating environment

        
Learn the world, test its physics, curate the disagreement

        
The long-term project is not a model pretending that Linux commands worked. David-GPT-2 supplies a learned prior over this particular filesystem; a controller proposes observable behavior; a policy decides when belief is insufficient; and a sandboxed Linux oracle supplies ground truth. Every comparison can become a structured operational trace for a later generation.

LOOP 03
Curriculum learning
The ensemble may nominate durable completed history, but only a human-authorized pipeline can approve data or launch another fine-tune.

Controlled learning loop

        
The final ensemble can nominate its own next training examples

        
With training functions explicitly enabled, the Gemma-owned final ensemble may tag an earlier completed-history window as a candidate or stage an on-demand fine-tuning request. The host, not the model, supplies exactly the transcript window the model reviewed. Candidates are append-only, content-hashed, and unapproved by default; routine conversation is deliberately excluded unless the model identifies durable training value.

        
completed host-owned session history
        ↓ model nominates rationale + tags
append-only candidate ledger
        ↓ model requests a fine-tune
immutable session-separated dataset
        ↓ explicit operator authorization
configured trainer or no launch

        
A function call cannot approve its own data or launch training. Launch requires a separate operator flag and argv-only trainer configuration, and remains blocked while another David-GPT-2 training process is active. The current in-progress answer is never captured mid-generation; it becomes eligible on a later turn.

      

    


    

      

        
Custom dataset guide

        
Recreate the architecture with your own target voice

        
The reusable idea is role-reversed causal-language-model training: context belongs to the prompting side, while loss is applied only to the target person's continuation. Replace David's private corpus and identity labels with your own reviewed data; do not redistribute either model's weights or source conversations.

        
    
          
  1. Choose one target role
    Define whose continuation the small model predicts and which role supplies context. In this project, assistant/Sol text is context and David/user text is the supervised target. Keep that mapping explicit; do not mix both sides into one assistant target.
    2. 
          
  2. Normalize conversations
    Export ordered conversations with stable conversation and message IDs. Adapt `src/david_gpt2/archive.py` if your source is not the expected transcript layout. Preserve turn order, exclude system/tool metadata from visible training text, and assign train/validation/test splits by conversation rather than by isolated message.
    3. 
          
  3. Define task and role markers
    Replace or extend the structural tokens in the dataset builder for your target role. Mask task markers, context, padding, and role delimiters with label `-100`; supervise only the target body and its real end-turn token. Keep literal marker text escaped so authored strings cannot become control tokens.
    4. 
          
  4. Build and audit the private dataset
    python scripts/build_dataset.py \
  --archive /path/to/your/private-archive \
  --output data/processed \
  --context-length 512 --seed 37
python scripts/audit_literal_markers.py --dataset data/processed
python scripts/audit_supervision.py --dataset data/processed
pytest -q
    Review decoded labels locally. Every intended target occurrence should have complete token coverage, with no cross-split conversation leakage and no private target text in reports.
    5. 
          
  5. Curate without rewriting the frozen source
    python scripts/dataset_workbench.py
    The local workbench presents searchable human-readable context and supervised targets. Add, rewrite, remove, or restore individual entries through a reversible overlay, then materialize and validate a versioned candidate. Opening the editor or building a candidate never starts training.
    6. 
          
  6. Run a real smoke fine-tune
    python scripts/smoke_test.py --config configs/smoke-test.yaml
    A smoke checkpoint validates mechanics, stop behavior, save/reload, and CUDA memory. It does not establish voice quality. Compare base and fine-tuned output before authorizing a full run.
    7. 
          
  7. Train and select the checkpoint
    python -m david_gpt2.train --config configs/combined.yaml
python -m david_gpt2.evaluate \
  --model outputs/david-gpt2-combined/best \
  --dataset data/processed/combined/test
    Copy `configs/combined.yaml`, then adjust paths and mixing ratios deliberately. Select `best` by supervised validation loss and inspect unrelated negative prompts for memorization or mode collapse.
    8. 
          
  8. Prepare Gemma and your identity prompt
    ollama pull hf.co/zaakirio/gemma-4-12b-it-uncensored-GGUF:Q5_K_M
ollama create gemma4-12b-q5-chat -f /path/to/Modelfile
    You may substitute another Ollama model that exposes streamed `message.thinking`, but verify its API fields and template. Create a separate system prompt for the final model's identity; do not train that identity implicitly into the target-role GPT-2 unless that is a deliberate dataset goal.
    9. 
          
  9. Point the bench at your checkpoint
    python david_gpt2_gemma_dialogue.py \
  --david-model /path/to/your/checkpoint \
  --mode dialogue --show-internal \
  --gemma-checkpoint-tokens 192 \
  --gemma-primer-tokens 128
    Rename UI labels and role markers in a fork, but preserve the boundary: Gemma creates a prose seed, the small model continues that seed as its target role, and a later Gemma request owns the final visible answer.
    10. 
          
  10. Add retrieval only after the baseline works
    Run first with knowledge off. If you add retrieval, point `DAVID_CONTINUATION_KNOWLEDGE_URL` at your own read-only query endpoint. The endpoint must return ranked `results` containing `text`, `path`, and `chunk`.
