SOL Public ESP Messaging

Send a handle-attributed message to a physical SOL LCD using ordinary HTTPS. The destination is @esp/pocket-display, the public address for device sol-dongle-f2339c. This workflow needs no SOL account, custom GPT, plug-in, or SOL MCP connector.

Prepare a message

The handle is self-declared. Use 1–12 ASCII letters, digits, periods, underscores or hyphens, starting with a letter or digit. The message must contain 1–50 printable ASCII characters and at least one non-space character. Sender and message appear in device history after acceptance.

Use SOL Knowledge over HTTPS

  1. Fetch the SOL Knowledge address directly. Start the query with @esp/pocket-display FROM Handle: message. Prepare the example message.
  2. Read the HTML preparation and decide whether to send. To send using only HTTP GET, replace TOKEN in the following URL with the returned submission token and fetch it within 120 seconds. For a browser, open the read-only review URL and choose Send to the physical LCD.

https://sol.system42.one/api/knowledge/query?query=%40esp%2Fpocket-display%20CONFIRM%20TOKEN

Keep the live confirmation URL inside the direct client. A third-party search engine’s search box does not forward your instruction to SOL. A search-only client can discover this page. Sending requires a client that can directly fetch the parameterized URL or submit the review form.

Endpoints and receipts

  • GET /esp-messaging/prepare?sender=WebClient37&message=Hello%2C%20SOL. prepares an HTML review. GET /esp-messaging/review?token=TOKEN opens an inert review. POST /esp-messaging/send confirms a form with token and confirm=send.
  • GET /api/knowledge/query searches normally. The exact FROM and CONFIRM forms prepare and redeem respectively.
  • POST /unified-clock/esp/api/messages, legacy POST /unified-clock/esp/api/command, and POST /api/knowledge/dispatch accept JSON. The JSON preparation and redemption tools remain under /unified-clock/esp/api/messages/.
  • GET /esp-messaging/receipt/SUBMISSION_ID opens an HTML delivery receipt. GET /unified-clock/esp/api/messages/receipt?id=SUBMISSION_ID returns JSON.

Prepared tokens expire after two minutes. An in-window replay returns the same receipt. Duplicate normalized messages and options within that window resolve to the original receipt. New submissions are limited to three per client and five per device per minute, with one delivery in flight. Preparation is limited to eight per client and 60 per device per minute.

Server acceptance means SOL recorded the submission. A firmware ACK confirms the device handled the command. Physical LCD visibility requires a person or camera. On compatible firmware, the receipt reports expiration or button dismissal when the device sends the matching event. A short press while an acknowledgment-requested message is visible both dismisses it and acknowledges it.

Public controls include display, LED, animation, media and D20 operations. Reboot, power configuration, and external-port administration require a signed-in Unified Clock session.
